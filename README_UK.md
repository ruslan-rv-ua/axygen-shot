# Axygen Shot

[![CI](https://github.com/ruslan-rv-ua/axygen-shot/actions/workflows/ci.yml/badge.svg)](https://github.com/ruslan-rv-ua/axygen-shot/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Release](https://img.shields.io/github/v/release/ruslan-rv-ua/axygen-shot)](https://github.com/ruslan-rv-ua/axygen-shot/releases/latest)

Портативний CLI-інструмент для Windows, який захоплює конкретні вікна застосунків як скріншоти. Розроблений насамперед для незрячих розробників, він забезпечує швидкий робочий процес з використанням виключно клавіатури для захоплення, збереження та передачі скріншотів ШІ-асистентам для візуального опису.

**[English version](README.md)**

## Основні можливості

- Захоплює конкретне вікно за назвою процесу або підрядком заголовка.
- Автоматично зберігає PNG-скріншоти з позначками часу у вказану підтеку проекту.
- Копіює результат просто в буфер обміну (саме зображення, шлях до файлу або обидва варіанти).
- Відтворює спеціальні відмінні звукові сигнали про успішне або невдале виконання.
- Може працювати безперервно у фоновому режимі (демон) із глобальною гарячою клавішею для серійних знімків.

## Встановлення

### Через Scoop (Рекомендовано)

```powershell
scoop bucket add ruslan-rv-ua https://github.com/ruslan-rv-ua/scoop-bucket
scoop install axygen-shot
```

### Встановлення вручну

1. Завантажте останній реліз зі сторінки [Releases](https://github.com/ruslan-rv-ua/axygen-shot/releases/latest).
2. Розпакуйте архів.
3. Перемістіть обидва файли `shot.exe` та `shot-watch.exe` в одну теку.
4. Переконайтеся, що ця тека додана до змінної середовища вашої системи `PATH`.

Вимоги: Windows 10 або новіша версія (x86-64).

## Швидкий старт

Перейдіть до теки вашого проекту та ініціалізуйте конфігурацію для застосунку, вікно якого потрібно захопити (наприклад, вашого браузера або емулятора):

```powershell
cd my-project
shot --init --process=myapp.exe
```

Ця команда створює файл `shot.toml` у поточній теці. Щоб зробити скріншот, просто виконайте команду:

```powershell
shot
```

Програма непомітно захопить вікно `myapp.exe`, збереже PNG-файл у теку `screenshots/`, скопіює шлях до файлу в буфер обміну та відтворить звук підтвердження.

## Конфігурація

Axygen Shot використовує файл налаштувань `shot.toml`. Інструмент шукає цей файл починаючи з поточної теки та підіймаючись вгору по дереву каталогів. Зазвичай зручно розмістити його в корені вашого проекту (наприклад, поруч із `.git`).

### Параметри конфігурації

```toml
# shot.toml
process   = "myapp.exe"          # Збіг вікна за назвою процесу
# title   = "MyApp"              # Альтернативно: збіг за підрядком заголовка (логіка АБО)
folder    = "screenshots"        # Тека для збереження файлів (за замовчуванням: "screenshots")
clipboard = "path"               # Що копіювати в буфер: "path", "image" або "both" (за замовчуванням: "path")
# hotkey  = "Win+F12"            # Гаряча клавіша для фонового режиму (за замовчуванням: "Win+F12")
```

Як мінімум, необхідно вказати або `process`, або `title`. Інші поля є суворо необов'язковими та використовують розумні значення за замовчуванням.

## Посібник із використання

Axygen Shot можна виконувати як одноразову команду або залишати працювати безперервно у фоні.

```text
shot                        Захопити визначене вікно один раз і завершити роботу
shot my-custom-label        Захопити вікно і додати "my-custom-label" до назви файлу
shot --watch                Запустити фоновий демон із реакцією на гарячу клавішу
shot --list-windows         Показати список усіх вікон, доступних для захоплення зараз
shot --check                Перевірити коректність конфігурації без створення скріншота
shot --init                 Створити порожній шаблон shot.toml у поточній теці
shot --init --process=app   Створити заповнений файл shot.toml
shot --version              Відобразити версію інструменту
shot --help                 Відобразити інформацію з довідки
```

### Тимчасове перевизначення параметрів

Будь-яке налаштування з `shot.toml` можна перевизначити напряму за допомогою аргументів командного рядка:

```powershell
shot --process=other.exe --clipboard=both --folder=snaps "alternative-label"
```

### Фоновий режим (Watch Mode)

Якщо вам потрібно робити повторні знімки без перемикання уваги з цільового вікна, використовуйте Watch Mode:

```powershell
shot --watch
```

Це запустить фоновий демон, який очікує на натискання глобальної гарячої клавіші (`Win+F12` за замовчуванням). У системному треї з'явиться іконка інструменту, де через правий клік можна перезапустити процес або вийти. Для уникнення конфліктів у системі може бути запущений лише один екземпляр демона одночасно.

### Вивід формату та зворотний зв'язок

Кожна операція супроводжується текстовим виводом у консоль та звуком.

**Успішне виконання:** Відтворюється короткий звук підтвердження, програма завершується з кодом 0 і виводить:
```text
status: ok
file: C:\projects\myapp\screenshots\2025-01-15_143022345_myapp-main-window.png
clipboard: path
```

**Помилка:** Відтворюється характерний звук помилки (декілька тонів), програма завершується з ненульовим кодом і виводить зрозумілі деталі проблеми у стандартний вивід помилок (stderr).

## Розробка

Цей розділ призначений для розробників, які модифікують програму або збирають інструмент із вихідного коду.

> **Чому два виконуваних файли?** `shot.exe` є стандартним консольним додатком, що гарантує синхронне очікування процесів командною оболонкою. `shot-watch.exe` спеціально скомпільовано як GUI-додаток для Windows, що дозволяє фоновому демону у системному треї працювати непомітно, не викликаючи появи чорного вікна консолі. Дивіться [ADR-002](docs/ADR-002-dual-binaries.md) для більш глибокого технічного контексту.

### Збірка з вихідного коду

Вимоги: Rust версії 1.87 або новішої.

```cmd
cargo build --release
```
Скомпільовані файли виводяться у `target\release\shot.exe` та `target\release\shot-watch.exe`.

### Спільні завдання для розробки

Проект використовує `just` для автоматизації:

```cmd
just ci              # Перевірка лінтера, перевірка форматування та запуск усіх модульних тестів
just build           # Релізна збірка
just size            # Релізна збірка з виводом розміру фінальних бінарних файлів
```
Або використовуйте Cargo безпосередньо:
```cmd
cargo test
cargo clippy -- -D warnings
cargo fmt -- --check
```
